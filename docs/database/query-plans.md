# Captured PostgreSQL query plans

Generated by `PostgresFeaturesIT.queryPlans` against a real embedded PostgreSQL 14.10 (no Docker). Source: `backend/platform-service/target/query-plans.txt`, copied here after the final build.

**Setup:** EXPLAIN (ANALYZE, COSTS OFF) on PostgreSQL with 100,000 synthetic transactions over 20 accounts - the SHAPE of the plan matters; timings are omitted on purpose (shared dev machine)

## Account history for a SPARSE account (planner switches to the per-account indexes)

```sql
select * from transactions where (source_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c' or target_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c') order by created_at desc, id limit 20
```

```text
Limit (actual rows=1 loops=1)
  ->  Sort (actual rows=1 loops=1)
        Sort Key: created_at DESC, id
        Sort Method: quicksort  Memory: 25kB
        ->  Bitmap Heap Scan on transactions (actual rows=1 loops=1)
              Recheck Cond: ((source_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c'::uuid) OR (target_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c'::uuid))
              Heap Blocks: exact=1
              ->  BitmapOr (actual rows=0 loops=1)
                    ->  Bitmap Index Scan on ix_tx_source_created (actual rows=0 loops=1)
                          Index Cond: (source_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c'::uuid)
                    ->  Bitmap Index Scan on ix_tx_target_created (actual rows=3 loops=1)
                          Index Cond: (target_account_id = 'e06be2e5-2a8a-467b-8400-802fa1203d1c'::uuid)
```
